## 概要と背景

大規模言語モデル（LLM）の推論処理における最大のボトルネックは、GPUの計算能力（FLOPS）ではなく**メモリ帯域幅（Memory Bandwidth）**にあります。

LLMの標準的な自動回帰（Autoregressive）デコーディングでは、1つのトークンを生成するたびに、モデルの全重みパラメータ（数十GB〜数百GB）をVRAM（HBM）からGPUコアのSRAMへ読み出す必要があります。特にバッチサイズが小さい（Batch Size = 1）インタラクティブな対話アプリケーションなどでは、GPUの演算器はほとんどの時間、メモリからのデータ転送を待っている状態（Memory-bound）になっています。

この「メモリ帯域制限によるレイテンシの遅延」を数学的な損失（モデルの出力品質低下）なしに解決する革新的な技術が**Speculative Decoding（推測デコーディング）**です。

本記事では、Speculative Decodingの基本原理である「仮説生成と一括検証」から、その進化形として特徴量空間での推測とツリー構造検証を組み合わせた**EAGLE (Extrapolating Auto-regressive Generation for LLM Acceleration)** のメカニズムまでを深掘り解説します。

## 技術的メカニズム・特徴

### 1. なぜメモリ帯域がネックになるのか？（Arithmetic Intensity）

GPU推論の効率は**算術強度（Arithmetic Intensity = 計算量 [FLOPs] / 転送バイト数 [Bytes]）**で評価されます。

- **Prefillフェーズ（プロンプト処理）**: 入力シーケンス全体を一度に行列積演算するため算術強度が高く、GPUの演算能力をフルに活用できます（Compute-bound）。
- **Decodeフェーズ（トークン生成）**: 1トークン生成ごとに過去のKVキャッシュとモデル重みを全ロードします。パラメータ数を $P$、精度を16bit（2 Bytes）とすると、1トークン生成あたり最小でも $2 \times P$ バイトの転送が発生します。例えば70Bモデルの場合、1トークンごとに約140GBのデータ転送が必要ですが、実行される計算量は僅かです（Memory-bound）。

### 2. Speculative Decodingの基本原理

Speculative Decodingは、**「軽量で高速なドラフトモデル（Draft Model）」**と**「高精度なターゲットモデル（Target Model）」**の2つのモデルを組み合わせて動作します。

```
[Draft Model (軽量・高速)]
  │ 1トークンずつ高速にk個の候補トークンを推測生成
  ▼
Draft Tokens: [x_1, x_2, x_3, ..., x_k]
  │
  ▼
[Target Model (大型・高精度)]
  │ 1回のフォワードパスで k個のトークンを一括検証（Parallel Verification）
  ▼
[検証 & 受容判定 (Speculative Verification)]
  ├─ Accept: x_1, x_2, x_3 (確率分布に合致)
  └─ Reject: x_4 (不一致) ───> Target Modelが補正トークン x_4' を生成して打ち切り
```

1. **ドラフト生成（Drafting）**: 小さなドラフトモデル（例: 7Bモデルに対する1Bモデル、あるいは同一モデルの量子化版）が、自動回帰的に $k$ 個のトークン候補を素早く生成します。
2. **並列検証（Parallel Verification）**: ターゲットモデルは、$k$ 個のトークン候補を含めたシーケンスを1回のフォワードパスで並列処理します。Prefillフェーズと同様に算術強度が高くなるため、1トークンを生成するのとほぼ変わらない時間で $k$ 個のトークン位置における確率分布を一度に計算できます。
3. **拒絶サンプリング（Rejection Sampling）**: ターゲットモデルの確率分布 $P(x)$ とドラフトモデルの確率分布 $Q(x)$ を比較し、理論的な出力分布を変えないようにトークンを受容（Accept）または棄却（Reject）します。

#### 数学的保証（Rejection Sampling）
ドラフトモデルからサンプリングされたトークン $x$ を採用する確率は以下のように定義されます。

$$ p_{\text{accept}}(x) = \min\left(1, \frac{P(x)}{Q(x)}\right) $$

もしトークンが棄却された場合、以下の再サンプリング分布 $P'(x)$ から新たなトークンを1つ生成してドラフトを打ち切ります。

$$ P'(x) = \frac{\max(0, P(x) - Q(x))}{\sum_y \max(0, P(y) - Q(y))} $$

このアルゴリズムにより、**ターゲットモデル単体でサンプリングした場合と完全かつ厳密に同一の確率分布から出力が得られる**ことが数学的に証明されています。

### 3. EAGLE：特徴量空間予測とTree-Attentionによる進化

従来のSpeculative Decodingには「ドラフトモデルの言語生成能力が低いためAccept率が上がりにくい」「ドラフトモデル自身のKVキャッシュ管理や推論オーバーヘッドが無視できない」という課題がありました。

これらを刷新したのが**EAGLE（EAGLE-1 / EAGLE-2）**です。

```
【従来のアプローチ】
Draft Token (x_t) ──> Draft Model ──> Draft Token (x_{t+1})  [トークンレベル推測]

【EAGLEのアプローチ】
Hidden State (h_t) ──> EAGLE Head (軽量Transformer層) ──> Hidden State (h_{t+1}) [特徴量レベル推測]
                                                               │
                                                               ▼
                                                      Token & Tree Candidate
```

EAGLEの主な技術的特徴は以下の3点です。

1. **Feature-level Extrapolation（特徴量レベルの外挿）**:
   EAGLEはトークン（離散値）を予測するのではなく、ターゲットモデルの最上層の**内部状態（Hidden States）**の遷移を1層の軽量なTransformerデコーダー層（EAGLE Head）で予測します。高次元の特徴量空間で予測することで、トークンレベル予測よりもはるかに豊かな文脈情報を維持できます。
2. **Tree-Structured Draft Construction（ツリー構造の候補生成）**:
   単一のシーケンス（チェーン）ではなく、複数の分岐を持つ「トークンツリー」を動的に生成します。
3. **Tree-Attentionによる並列一括検証**:
   作成されたツリー構造に対して、カスタムしたAttention Mask（Tree-Attention）を適用し、ターゲットモデルで1度に全分岐を検証します。いずれか最も長い確率的正当性を持つパスが採用されます。

## 実装・活用コード例

ここでは、Speculative Decodingの核心となる**拒絶サンプリング（Rejection Sampling）のロジック**を概念的に理解するためのPyTorch実装例と、最新の推論エンジンで実際に使用するコード例を示します。

### 1. Rejection Samplingのアルゴリズム実装（Python/PyTorch）

以下は、ターゲットモデルとドラフトモデルが出力したロジット（Logits）から、推測デコーディングの受容・棄却判定を行う核心アルゴリズムのPython実装です。

```python
import torch
import torch.nn.functional as F

def speculative_rejection_sampling(
    target_logits: torch.Tensor,  # Shape: [k, vocab_size]
    draft_logits: torch.Tensor,   # Shape: [k, vocab_size]
    draft_tokens: torch.Tensor,   # Shape: [k]
    temperature: float = 1.0
) -> torch.Tensor:
    """
    Speculative DecodingにおけるRejection Samplingの検証ロジック
    
    Returns:
        accepted_tokens: 採用されたトークン列（末尾に補正トークンを含む）
    """
    k = draft_tokens.shape[0]
    accepted_tokens = []
    
    # 確率分布の計算
    p = F.softmax(target_logits / temperature, dim=-1) # Target
    q = F.softmax(draft_logits / temperature, dim=-1)  # Draft
    
    for i in range(k):
        token_id = draft_tokens[i].item()
        p_val = p[i, token_id].item()
        q_val = q[i, token_id].item()
        
        # 受容確率 p_accept = min(1, P(x) / Q(x))
        p_accept = min(1.0, p_val / (q_val + 1e-10))
        rand_val = torch.rand(1).item()
        
        if rand_val < p_accept:
            # トークンを受容
            accepted_tokens.append(token_id)
        else:
            # 棄却された場合：再サンプリング P'(x) = max(0, P(x) - Q(x)) / norm
            p_prime = torch.relu(p[i] - q[i])
            p_prime_sum = p_prime.sum()
            
            if p_prime_sum > 0:
                p_prime = p_prime / p_prime_sum
                corrected_token = torch.multinomial(p_prime, num_samples=1).item()
            else:
                corrected_token = torch.multinomial(p[i], num_samples=1).item()
                
            accepted_tokens.append(corrected_token)
            # 棄却された時点でドラフトの検証を終了
            return torch.tensor(accepted_tokens, dtype=torch.long)
            
    # 全てのドラフトトークンが受容された場合、Targetモデルからさらに1トークン追加でサンプリング
    next_token = torch.multinomial(p[-1], num_samples=1).item()
    accepted_tokens.append(next_token)
    
    return torch.tensor(accepted_tokens, dtype=torch.long)

# 動作確認用ダミーデータ
if __name__ == "__main__":
    vocab_size = 1000
    k = 4 # ドラフト数
    
    # ダミーのLogitsとドラフトトークン
    target_logits = torch.randn(k, vocab_size)
    draft_logits = torch.randn(k, vocab_size)
    draft_tokens = torch.randint(0, vocab_size, (k,))
    
    result = speculative_rejection_sampling(target_logits, draft_logits, draft_tokens)
    print(f"ドラフトトークン数: {k}")
    print(f"採用・出力トークン列: {result.tolist()}")
    print(f"採用トークン数: {len(result)}")
```

### 2. vLLMを用いた Speculative Decoding の実践コード

現実のプロダクション環境では、`vLLM` などの最適化推論エンジンを用いてSpeculative Decodingを簡単に有効化できます。以下は、メインモデルに `Llama-3-70B-Instruct`、ドラフトモデルに `Llama-3-8B-Instruct` を指定して推論を高速化するPythonスクリプト例です。

```python
from vllm import LLM, SamplingParams

def main():
    # Sampling条件の設定
    sampling_params = SamplingParams(
        temperature=0.7,
        top_p=0.95,
        max_tokens=256
    )

    # Speculative Decodingを有効にしたLLMエンジンの初期化
    llm = LLM(
        model="meta-llama/Meta-Llama-3-70B-Instruct",
        tensor_parallel_size=4, # 70Bモデル用に4GPUに分散
        
        # Speculative Decodingの設定
        speculative_model="meta-llama/Meta-Llama-3-8B-Instruct", # Draft Model
        num_speculative_tokens=5, # 1回あたりに推測するトークン数 k
        use_v2_block_manager=True, # メモリ最適化
    )

    prompts = [
        "Speculative Decodingの原理について、メモリ帯域幅の観点から簡潔に説明してください。",
        "Pythonでクイックソートを実装し、時間複雑度について解説してください。"
    ]

    # 推論の実行
    outputs = llm.generate(prompts, sampling_params)

    for output in outputs:
        prompt = output.prompt
        generated_text = output.outputs[0].text
        print(f"\n--- Prompt: {prompt} ---")
        print(f"Generated:\n{generated_text}")

if __name__ == "__main__":
    main()
```

## まとめ

LLM推論の速度限界を打破するSpeculative DecodingとEAGLEの重要ポイントをまとめます。

1. **ボトルネックの転換**: DecodeフェーズにおけるGPUのメモリ帯域制限（Memory-bound）を、並列検証による計算（Compute-bound）に置き換えることで推論速度を向上させる。
2. **数学的な無損失性**: Rejection Samplingアルゴリズムにより、ターゲットモデル単体で出力する場合と**数学的に100%同一の出力品質（確率分布）**を維持できる。
3. **EAGLEの革新**: 従来の離散トークン推測から「内部状態（Hidden States）の特徴量推測＋Tree-Attention」へと進化させたことで、Accept率を高め、ターゲットモデルの2〜3倍の加速を達成した。

ローカル環境やエッジデバイスにおける小型モデルの活用から、クラウド基盤における大型モデルのサービングコスト削減まで、Speculative Decoding技術は現代のAIインフラストラクチャにおける最重要コンポーネントの一つとなっています。
