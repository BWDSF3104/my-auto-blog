# アフィリエイトキーワード選定ロジックの見直し (2026-10-08)

**状態: 実装完了・pytest検証済み (2026-10-09)。** E2E（GitHub Actions）未検証。

## 問題

楽天API商品カード実装後のローカルテストで、キーワードが汎用的すぎたため**記事テーマと無関係な商品**が返される問題が判明した。

### 実際のマッチ例（2026-10-08 ローカルテスト）

| キーワード | 返された商品 | 問題点 |
|-----------|-------------|--------|
| ケモノ | 動物モチーフペンケース | 許容範囲 |
| ファンタジー | レディースパンプス（シューファンタジー） | 無関係（ブランド名由来） |
| SF | iPhoneガラスフィルム | 無関係（「SF」を略号として解釈） |
| 百合 | 浴衣福袋（百合の花柄） | 無関係（花の「百合」） |
| ケモノ ファンタジー | 化物語 DVD-BOX | 弱関連（「バケモノ」+「ファンタジー」） |
| ケモノ SF | ティッシュケース（SF-3521型番） | 無関係（型番由来） |
| ケモノ 百合 | 商品なし | - |

### 根本原因

1. **ジャンル単体キーワードが汎用的すぎる**: 「ファンタジー」「SF」「百合」は楽天市場では商品カテゴリとして広く使われるため、ケモノ記事の文脈とは無関係な商品がヒットする
2. **2語以上の組み合わせが型番・ブランド名と衝突する**: 「SF-3521」「シューファンタジー」のような型番・ブランド名に部分一致する
3. **記事の具体的な主題（例: アーctic hare anthro、cybernetic sparks）をキーワードに反映していない**: 現在は world_setting / relationship のみから生成しており、記事固有の要素が欠落

## 見直し候補

### 方向性A: キーワードの具体化
- ジャンル単体（「ファンタジー」「SF」）は**除外**し、必ず「ケモノ」複合で検索
- 記事の char_type / world_setting / relationship をより具体的に組み合わせ
- 例: 「ケモノ 獣人 ファンタジー」「ケモノ 百合 動物」

### 方向性B: Gemini生成商品名の活用
- `<!-- AFF_PRODUCT: "keyword" -->` プレースホルダー（比較表内）のキーワードを優先使用
- Geminiが記事文脈に基づいて商品名を生成するため、相対的に具体的
- 現在 `process_inline_products` で処理されているが、末尾セクションの `inject_affiliate_links` には反映されていない

### 方向性C: 検索結果の関連性フィルタ
- 楽天APIの返却商品名に記事の主要キーワード（char_type, world_setting）が含まれるかチェック
- 無関係と判定した商品はカードに含めない（フォールバック: 検索リンク方式）

### 方向性D: キーワード数の制限
- 現在は最大7kw（ケモノ1 + ジャンルN + 関係性1 + ケモノ+ジャンルN + ケモノ+関係性1）
- API呼び出しコスト・実行時間・無関係マッチのリスクを考慮し、上限を2-3kwに絞る
- 優先順位: Gemini商品名 > ケモノ+具体ジャンルの組み合わせ > 単体

## 根因分析 (2026-10-09 追記)

楽天APIのキーワード検索は**ANDマッチ（全単語が商品名・説明文に含まれる必要）** である。

| パターン | 挙動 | 実証（rakuten_cache.json / E2E） |
|---------|------|----------------------------------|
| 単体汎用語（ファンタジー/SF/百合） | ヒットするが無関係 | パンプス（「シュー**ファンタジー**」）/ iPhoneフィルム（「**SF**-3521」型番）/ 浴衣（花の「**百合**」柄） |
| 複合語（ケモノ 百合 / ケモノ ファンタジーとSF） | **0ヒット** | 全単語を含む商品が存在しないため |
| 単体「ケモノ」 | ヒット・許容範囲 | アニマルモチーフ商品（動物ペンケース等） |
| 英語 trend（On Stella Montis） | **0ヒット** | 日本語市場に該当商品なし |

**結論**: 「具体化＝複合語化」（方向性A単体）は0ヒットを悪化させるため**単独では非可解**。単体語はヒットしても無関係になる。両極端のどちらでもない「具体な単一語＋結果フィルタ」が解。

## 推奨案 (2026-10-09 確定・ユーザー承認)

**キーワードカスケード検索（最大3件）**: kemono_story 記事では、楽天を以下の順で検索し、**関連性フィルタ通過した商品が3件溜まったら即停止**。

### 1. カスケード順序（kemono_story）
| # | キーワード | 例 | 備考 |
|---|-----------|-----|------|
| 1 | Gemini生成の商品名 | BEASTARS 1 | `<!-- AFF_PRODUCT -->` / `product_recommendations`。記事文脈由来で最も具体的 |
| 2 | Gemini商品名の先頭句 | BNA | #1の緩和。「BNA 完全アニメ画集」→「BNA」。スペース＋区切り語（用的/向け/用/的）で分割し先頭セグメントを採用（「ケモノ娘用のポンチョ」→「ケモノ娘」）。平仮名1文字（の/に/へ/と/や）は単語内で使われるため区切りに使わない。固定文字数切断・日本語フィルタなし。区切れない1語は商品名と重複するためスキップ |
| 3 | ケモノ ＋ ジャンル名 | ケモノ ファンタジー | AND複合。ヒットは少ないが、ヒット時は単体ケモノより関連性高い |
| 4 | ケモノ ＋ キャラ関係性 | ケモノ 百合 | AND複合。0ヒット確認済み（ケモノ 百合） |
| 5 | ケモノ | — | 安全アンカー。アニマル系商品ヒット確認済み |
| 6 | 獣人 | — | 第2アンカー（獣人ライトノベル・グッズ等） |
| 7 | 動物 | — | 第3アンカー（より広いアニマル系） |

- **停止条件**: 関連性フィルタ通過した商品が3件溜まったら即停止（残りのキーワードは検索しない）
- **重複除去**: 既に検索したキーワードと同一ならスキップ（例: Gemini商品名が「ケモノ」の場合）
- **ジャンル単体語（ファンタジー/SF/百合）と関係性単体語はAPIに一切送らない**（ヒットしても無関係。検索リンクにのみ残す）
- **英語 trend キーワードもAPIに送らない**（0ヒット確定）
- **非ストーリー系（tech等）は別チェーン**: Gemini商品名 → 先頭句 → 既存の改善キーワード（「Python 本」等）

### 2. 関連性フィルタ（最重要）
商品が**フィルタ通過した場合のみ「3件溜まり」にカウント**。これで無関係商品がスロットを埋めるのを防ぐ。

- **kemono_story のコアトークン（固定リスト）**: `ケモノ / バケモノ / 獣人 / 獣 / 動物 / アニマル / anthro / beast`
  - 検証（`data/rakuten_cache.json` の実データ全6件）:
    - **通過（採用）**: ペンケース（「アニマル」「ワイルドアニマル」含む）/ 化物語DVD（「バケモノ」→「ケモノ」含む・関連アニメ）/ ティッシュ箱（「ナマケモノ」「動物」「アニマル」含む・アニマルモチーフ）✓
    - **不合格（除外）**: パンプス（「シューファンタジー」のみ）/ iPhoneフィルム（「SF」型番のみ）/ 百合浴衣（花の「百合」のみ）✓
  - 注: 「ケモノ」単体語でも「アニマル」商品にマッチするため、キーワード語の完全一致判定では不可（同義リストが必須）
  - 注: 動物モチーフ（ティッシュ箱等）はフィルタ通過するが、タスク許容基準「アニマルモチーフ＝許容範囲」と整合
- **その他（tech等）**: 検索キーワードの2文字以上の実語トークンが商品名に1つ以上含まれること

### 3. API予算
- 最悪7キーワード ×（1.5秒間隔＋リクエスト）≈ 11〜15秒。公式の1 application_id 毎1秒1リクエスト制限内
- 0ヒットも30日キャッシュ（現行挙動）のため、再実行の同一キーワードは無料
- 注: #3/#4 は0ヒットが多い（確認済み）ため、実効的に#5アンカー到達まで約4秒の無駄呼び出しがある。ユーザーの順序は具体性優先で維持（最適化したい場合アンカー前上げも可）

### 4. API複雑検索機能（公式仕様参照、2026-10-09確認）
楽天市場API v2026-07-01（`webservice.rakuten.co.jp/documentation/ichiba-item-search`）:

| 機能 | 可否 | 仕様根拠 |
|------|------|---------|
| OR検索 | **可能** `orFlag=1` | orFlag: 0=AND（デフォルト）/ 1=OR |
| OR＋AND併用 | **不可** | 仕様に「Complex search condition like "(A and B) or C" は使えない」と明記 |
| 正規表現 | **不可** | keywordはプレーンテキスト（スペース区切り）、正規表現の記述なし |
| アスタリスクワイルドカード（`*ケモノ`） | **不可** | ワイルドカード構文なし。単体`*`は無効（keyword最低2文字）、`*ケモノ`はリテラル文字列扱い→実質0ヒット |

実在するパラメータ（複雑条件の代替）:
- `NGKeyword` 除外キーワード → **AND NOT**（`keyword=ケモノ&NGKeyword=百合`＝ケモノから百合を除く）
- `genreId` ジャンル絞り → キーワード＋カテゴリのAND
- `field` 0=広め検索（一致多め）/ 1=厳しめ検索（一致少なめ）→ API内蔵の「広さ」切替
- 複数呼び出し＋クライアント側マージ →「(A AND B) OR C」を2呼び出しで実現

**設計メモ**: アンカー#5〜7（ケモノ/獣人/動物）は1回のOR呼び出し（`keyword=ケモノ 獣人 動物&orFlag=1`）に統合でき、最悪7回→5回に短縮可能。ただしOR結果は最も広い語「動物」に支配され、カスケードの「具体→汎用」優先順位が弱まる。**本設計は優先順位を維持するためOR非採用**（最悪7回でも1秒1リクエスト予算内・30日キャッシュ）。
