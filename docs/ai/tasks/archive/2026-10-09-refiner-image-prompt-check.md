# リファインプロンプトに画像プロンプト形式チェックを追加 (2026-10-09)

**状態: 完了 (2026-10-09)。** 実装完了・pytest検証済み。リファイナーの実Gemini挙動検証は未実施。

## 背景

- 「画像プロンプトに場面ごとの表情/ポーズ指定を追加」(2026-10-09) の実Gemini API検証で書式逸脱を観測: `gentle smile`（Danbooru単一タグでない自然言語句）1件、シーンキーワードに自然言語句2件
- 2-passリファイナー（`refine_story.txt` / `refine_tech.txt`）は現状「画像プロンプトを維持・変更しない」と明示指示されていた（旧82行目、構成と形式節）ため、Pass1の書式逸脱はリファイナーで無修正のまま通過
- Python側はフォールバック解析（legacy部分一致・共有タグ化）で黙って画像品質を劣化させるだけ
- 画像プロンプトの形式ルール（括弧形式、コロン=キャラ別表情、Danbooru実在タグ、6-10語、SFW、被り禁止）は Pass1テンプレートのみに記載（`kemono_story.txt:21-64`、`default.txt:65-70`、`ai_deep.txt:42-44`）

## 要件（ユーザー）

- リファイナー用のプロンプトの役割を広げ、「画像生成用プロンプトの書式が正しいことの確認」を担当させる
- 検討の選択肢（A: プロンプトのみ / B: Python構造化検証 / C: ハイブリッド）から**Aのみ**を採用

## 設計

- 各リファインプロンプトに「画像プロンプト形式チェック」新節を追加し、修正権限を**形式のみ**に厳密限定
  - 修正する（形式のみ）: 括弧の欠落・無効なcharacter_N参照（有効IDへ）、自然言語句→簡潔タグ、masterpiece等品質タグの削除、日本語・全角→英語・半角、表情欠落時の1-2タグ追加
  - 変更しない（内容）: シーンの選定・配置・枚数、シーンキーワードの意味、表情の意図、記事本文
- リファイナーは抽出（`extract_image_prompt`/`extract_character_prompts`）と画像生成より前に走るため、修正が `compose_image_prompt` と画像生成へ伝播。追加API呼び出しなし（既存Pass2の流用）
- 観測された逸脱（自然言語句・表情と場面の不一致）は意味的であり正規表現では完全には捕捉できず、プロンプトによるチェックが適切と判断
- B（Python構造化検証）は未実施。将来、逸脱頻度の定量化（警告ログ）として安全網を追加可能
