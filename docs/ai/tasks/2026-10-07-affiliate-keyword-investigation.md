## 概要
アフィリエイトリンクの検索キーワードを作成している箇所を整理し、#7（製品推薦の汎用化）と関連する項目を特定。

## 前提情報
- **A1/A2は1pass目のみ適用**。2pass目（`refine_story.txt`）はfrontmatterを維持するのみ

## A1: `product_recommendations` ルール (kemono_story.txt:98-101)

**関連度:** 直接修正対象

**役割:** AIにfrontmatterの `product_recommendations` YAMLブロックを生成させる

**現在の指示:**
```
【product_recommendations の指定ルール】
・物語のテーマ・世界観に関連する「実在する」書籍・グッズ・関連商品を2〜3つ選定してください。
・各商品には `name`（具体名）, `category`（書籍, フィギュア, ゲーム, ソフトウェア, ガジェット等）, `price_range`（例: 1000円台, 3000円台, 無料）を指定してください。
・架空の商品名は使用しないでください。有名なタイトルや実際に販売されている商品を選んでください。
```

**問題点:**
- 「物語のテーマ・世界観に関連する」という指示が抽象的
- AIが「ケモノ 図鑑」「ライトノベル おすすめ」などの汎用キーワードを選定する
- 具体例がないため、物語の具体的な要素（種族、キャラクター、設定）と商品を結び付けない

**処理フロー:**
`kemono_story.txt`のプロンプト → AIがfrontmatter YAML生成 → `extract_product_recommendations()` (L1739-1778) がパース → `generate_product_cards()` (L1784-1844) が商品カードHTML生成

**修整案:**
指定ルールに3行追加:
1. 物語の具体的な要素（種族、世界観、主要テーマ）から関連する版権・作品・ジャンルを特定し、その公式グッズや関連書籍を選ぶ
2. 具体例: 「狼の主人公が活躍するファンタジー」→ BEASTARS 関連グッズ、狼のイラスト集
3. 「ケモノ 図鑑」「ライトノベル おすすめ」などの汎用キーワードは避ける

## A2: 本文内プレースホルダー (kemono_story.txt:52-56)

**関連度:** 直接修正対象

**役割:** AIが本文内にアフィリエイトリンクのプレースホルダーを挿入する

**現在の指示:**
```
・物語の結末付近または最終章の末尾に【1箇所】、関連書籍・グッズへのアフィリエイトリンクプレースホルダーを挿入してください。
  挿入形式：<!-- AFFILIATE: "商品名" | "アンカーテキスト" -->
  例：<!-- AFFILIATE: "ケモノキャラクター図鑑 公式ガイド" | "ケモノキャラクターのイラスト集はこちら" -->
  ※ 物語の世界観を壊さないよう、エピローグや著者あとがきのような形で挿入してください。
  ※ 商品名は「実在する」具体的なタイトルを使用してください。曖昧な検索キーワードは避けてください。
```

**問題点:**
- 例が「ケモノキャラクター図鑑 公式ガイド」→ 架空の商品名
- 「曖昧な検索キーワードは避けてください」とあるが、AIは汎用キーワードを選定する傾向がある
- AIの自由裁量に任されており、品質にばらつきがある

**処理フロー:**
AIが `<!-- AFFILIATE: "kw" | "anchor" -->` を生成 → `process_inline_affiliates()` (L907-950) が正規表現で検出 → Amazon/楽天検索リンクに置換

**修整案:**
1. 例を架空商品名から実在する商品名に変更（例: "BEASTARS 1"）
2. 商品名の選定基準を明確化（物語の具体的な要素から連想される版権・作品）
3. 架空商品名や汎用キーワードを明示的に禁止

## S1: `_extract_article_keywords()` (generate_article.py:1095-1136)

**関連度:** 間接（#6のtags日本語化と連動）

**役割:** 記事本文からテーマキーワードを最大2件抽出

**ロジック:**
1. **tags優先** (L1106-1114): frontmatterの `tags:` からカンマ区切りで抽出。先頭から最大 `max_kw` 件を返す
   - 例: `tags: ["Kemono", "Novel", "Fantasy"]` → `"Kemono"`, `"Novel"`
2. **本文フォールバック** (L1117-1133): tagsがない、または不足している場合、本文先頭2段落から日本語文字列（2文字以上）を抽出
   - マークダウン記号を除去 → 正規表現 `[\u3040-\u309f\u30a0-\u30ff\u4e00-\u9fff]{2,}` で日本語単語を抽出
   - 例: 「狼の少年が…出会った黒豹の…」→ `"狼の"`, `"少年が"`, `"出会った"`, `"黒豹の"`

**問題点:**
- tagsが英語固定（`"Kemono"`, `"Novel"`, `"Fantasy"`）→ 検索キーワードも英語になる
- 日本語抽出は単なる連続文字列なので、意味のあるキーワードにならない

**処理フロー:**
抽出したキーワード → `_improve_keyword()` (L1045-1067) で改善 → `inject_affiliate_links()` でAmazon/楽天検索リンク生成

**修整案:**
- #6でtagsを日本語化（`["獣人", "ライトノベル", "ファンタジー"]`）することで検索キーワードも日本語化
- 本文フォールバックの抽出ロジックについては本タスクの範囲外

## S2: `_extract_affiliate_keyword()` (generate_article.py:1697-1733)

**関連度:** 間接

**役割:** trendタイトルからアフィリエイト検索用のキーワードを1つ抽出

**ロジック:**
1. e621タイトルは除外 (L1704)
2. `:` 区切りの場合は説明側を優先 (L1707-1719)
   - `owner/repo: description` → `repo`名を抽出（2-20文字）
   - 説明側が空でない場合は説明側をタイトルとして使用
3. 50文字超えは短縮 (L1721-1728)
   - 大文字始まりの単語（固有名詞候補）を最大3語に制限
   - 大文字がない場合は先頭4語
4. 特殊文字を除去して最大30文字に制限 (L1730-1733)

**問題点:**
- trendタイトルが英語の場合、抽出されるキーワードも英語
- GitHubリポジトリ名は後段で除外されるが、trendデータ自体が技術系偏重

**使用箇所:**
`_append_trending_topics()` でtrendデータから集約→ `inject_affiliate_links()` に `trend_keywords` として渡される

**修整案:**
- 本タスクの範囲外。trendデータ自体の改善が前提。

## F1: `_is_affiliate_bad_keyword()` (generate_article.py:1031-1042)

**関連度:** 間接（防御的な安全網）

**役割:** アフィリエイト検索に適さないキーワードを除外

**現在のフィルタ条件:**
1. 2文字未満 (L1034)
2. 特定のプレフィックスで始まる (L1036-1037):
   - `"a "`, `"an "`, `"the "`, `"how to"`, `"what is"`, `"why "`, `"best "`, `"top "`, `"new "`, `"latest"`, `"review"`, `"tutorial"`, `"guide "`
   - `"e621"`, `"github"`, `"repo "`, `"repository"`, `"source code"`, `"open source"`, `"free "`, `"download"`, `"install"`, `"setup "`
3. 半角英数字のみ + スペース3回以上 (L1040)

**問題点:**
- 日本語の汎用キーワード（「ケモノ 図鑑」「ライトノベル おすすめ」等）をフィルタできない
- A1, A2のAI生成キーワードには適用されない（S1, S2のスクリプト抽出のみ）

**修整案:**
`_AFFILIATE_BAD_KEYWORDS_JP` 定数を追加して日本語の汎用キーワードも除外:
```python
_AFFILIATE_BAD_KEYWORDS_JP = {
    "ケモノ 図鑑", "ライトノベル おすすめ", "ファンタジー 小説",
}
```
関数内に完全一致チェックを追加。防御的な安全網であり、主要な修正対象（A1, A2）には効かない。

## `_KEYWORD_ENHANCEMENT` 辞書 (generate_article.py:1008-1028)

**関連度:** 間接

**役割:** 一般的なタグを購買意欲の高い検索語に置換

**現在の辞書:**
```python
_KEYWORD_ENHANCEMENT = {
    "tech": "プログラミング 入門書",
    "ai": "AI 入門 書籍",
    "kemono": "ケモノ 図鑑",
    "pokemon": "ポケモン 公式",
    "novel": "ライトノベル おすすめ",
    "fantasy": "ファンタジー 小説",
    "game": "ゲーム 周辺機器",
    "programming": "プログラミング 本",
    "web": "Web開発 書籍",
    "javascript": "JavaScript 本",
    "python": "Python 本",
    "rust": "Rust 本",
    "react": "React 書籍",
    "vue": "Vue.js 本",
    "next": "Next.js 書籍",
    "docker": "Docker 入門",
    "linux": "Linux 本",
    "css": "CSS 本",
    "html": "HTML 本",
}
```

**マッチ対象:** 記事の frontmatter `tags:` 配列（例: `["Kemono", "Novel", "Fantasy"]`）が主。trendタイトルが補充。

**問題点:**
- `"kemono"` → `"ケモノ 図鑑"`: 汎用すぎる
- `"novel"` → `"ライトノベル おすすめ"`: 購買意欲の低い検索語
- `"fantasy"` → `"ファンタジー 小説"`: 同上
- 辞書マッチは部分一致なので、`"kemono"` が含まれる任意のキーワードが `"ケモノ 図鑑"` に置き換わる
- 技術系が大半を占めており、物語系に特化した改善語がない

**修整案:**
物語系のエントリを削除:
- `"kemono"`, `"novel"`, `"fantasy"` を削除（S1でtagsが日本語化されるため不要）
- `"pokemon"` は維持（通常の作品名であり、trendから除外されていない。キーワード改善として有効）

## `_improve_keyword()` (generate_article.py:1045-1067)

**関連度:** 間接

**役割:** 抽出したキーワードを購買意欲の高い検索語に改善

**ロジック:**
1. `_KEYWORD_ENHANCEMENT` 辞書で部分一致する場合は置換 (L1053-1055)
2. prompt_typeに応じたサフィックス付与 (L1058-1066)
   - 技術系: 英単語のみ → `"{kw} 書籍"`、それ以外 → `"{kw} 関連グッズ"`
   - 物語系: `"{kw} 関連作品"`

**問題点:**
- 物語系のサフィックス `"関連作品"` は検索ボリュームが低い
- 辞書マッチが部分一致なので意図しない置換がかかる

**修整案:**
物語系のサフィックスを削除してキーワードをそのまま使用:
- `"関連作品"` を空文字列に変更（例: `"BEASTARS 関連作品"` → `"BEASTARS"`）
- 作品名のみで検索すれば商品がヒットする。余計なサフィックスは検索結果を狭めるだけ
- A1/A2のプロンプト修正でAIが具体的な商品名を生成するようになり、スクリプト側の干渉は最小限でよい
