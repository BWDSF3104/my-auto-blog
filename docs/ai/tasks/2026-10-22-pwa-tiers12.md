backlog の P3 #2（PWA 対応）+ #3（Service Worker）を**Tier 1+2 の範囲で実施**する。
ユーザー指示: 「2までの実施で終わるのは可能か？」→ 可能と判断し「**2まで実施、3は棄却**」。

- 実施: **Tier 1**（manifest + アイコン → インストール可能）+ **Tier 2**（静的アセットのみ cache-first の Service Worker）
- 不採用: **Tier 3**（画像 50MB LRU キャッシュ管理）— 理由: 1 記事/日 ~50KB 程度の通信節約のみ。⭐⭐⭐ 難易度の LRU ロジック・quota 監視・304 罠・ブラウザ差の運用コストに見合わない
- 決定: `docs/ai/decisions/2026-10-22-pwa-tier2.md` に記録。backlog-archive.md に不採用行追加

## 調査結果 / 変更内容

**前提（調査で確認）:**
- `src/pages/*` + `src/layouts/PostLayout.astro` の 9 箇所に `<html>/<head>` が重複（共有 head コンポーネントなし）
- 全リソース HTTP ヘッダー（curl 確認）: `Cache-Control: max-age=600` + `ETag` + `Last-Modified`（GitHub Pages 制御、カスタムヘッダー不可）
- 画像: 199 枚 / 平均 53KB（public/images/）— **キャッシュ対象外（Tier 3 不採用のため）**
- 既存 SW なし。`public/` に favicon.svg / favicon.ico
- 9 箇所の head: 各ページ独立の meta（title/description/canonical/OGP 等はページ特定、骨格 meta は共通）

**変更内容:**
- 新規 `public/manifest.json`: name / start_url / scope `/my-auto-blog` / display standalone / theme_color #f1f5f9 / icons（icon-192 / icon-512 / favicon.svg any）
- 新規 `public/icon-192.png` / `public/icon-512.png`: PIL で生成（slate-900 丸角背景 + 白「B」、favicon.svg のブランド色 #0f172a / #f8fafc に合わせ）
- 新規 `public/sw.js`: 静的アセット（css/js/svg）のみ cache-first。SW 内 fetch は `cache: 'no-store'` で HTTP キャッシュ経由の 304（空ボディ）を SW キャッシュに保持しないことを保証。HTML・画像・API は透過（network のみ、SW キャッシュなし）
- 各 head（8 ページ + PostLayout）: `<link rel="manifest" .../manifest.json>` + `<meta name="theme-color" content="#f1f5f9" />` 追加
- 各 body 末（8 ページ + PostLayout）: SW 登録スクリプト追加（`navigator.serviceWorker.register('/my-auto-blog/sw.js')`、catch で無視）
- backlog.md: P3 #2, #3 項目削除 + 推奨実行順序テーブル 4 行目削除・再编号（5→4, 6→5）
- backlog-archive.md: 行 #20 追加（PWA 画像 50MB LRU、ユーザー不採用 2026-10-22）
- 新規 `docs/ai/decisions/2026-10-22-pwa-tier2.md`: ティアー選択・不採用理由

**実装判断:**
- SW の pre-cache（`caches.open().addAll()`）は**不使用**: `_astro/*` ハッシュはデプロイごとに変わるため、install 時の addAll は次回ビルドで 404 失敗 → SW 更新が止まるリスク
- 静的アセットは **URL ハッシュ付き** → 旧キャッシュは自動で無効化（URL が変わるため参照されなくなる）
- SW 登録は各ページ末（body 末）に 1 回、スコープ `/my-auto-blog`
