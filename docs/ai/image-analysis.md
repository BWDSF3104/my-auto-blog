# 画像認識（Groq MCP ツール）使い方・メンテナンス

MCP ツール `analyze_image_with_groq` を用いた画像の視覚解析（スクリーンショットの文字/UI 読み取り、レイアウト検証、生成画像の確認など）の使い方とメンテナンス手順。

## ツール概要

| 項目 | 値 |
|---|---|
| MCP サーバー本体 | `C:\OtherApp\groq_image_mcp\server.py`（FastMCP, stdio transport） |
| ツール名 | `analyze_image_with_groq` |
| モデル | Groq `qwen/qwen3.8-27b`（vision） |
| 動作 | ローカル画像を base64 化して Groq API へ送信し、**説明文（テキスト）のみ**を返す |
| 対応形式 | PNG / JPG / JPEG / WEBP |
| サイズ上限 | 20 MiB（`MAX_BYTES`） |
| 質問の長さ | 8000 文字で切詰め（`question[:8000]`） |
| 最大生成トークン | 1200 |

**注意**: 画像はクラウド（Groq API）へ送信される。Kilo 自身の作成による画像やプロジェクトフォルダ内の画像は確認不要。画像に機微・個人情報を含む場合は事前にユーザーの確認を取る。

## 使い方

### 基本呼び出し

`image_path` にローカル画像の絶対パスを指定して呼び出す。デフォルト質問で「自然で正確な日本語での説明文、文字・エラーの正確な転記、判読不能箇所の明示」が得られる。

```
analyze_image_with_groq(image_path="D:\...\screenshot.png")
```

### 焦点化分析（検証ポイントを指定する）

`question` パラメータに具体的な質問を列挙すると、目的の検証に絞った回答が得られる。

- 1 回の質問に**検証項目は 2〜6 個程度**に抑える
- 色・形状などの細部は実行ごとにブレることがあるため、重要項目は質問を 1〜2 個に絞って再実行する
- 定型回答を求めたい場合は「なければ『〜は見つからない』と明記すること」といった指示を書く

**使用例**:

- レイアウト変更後のスクリーンショット検証: 「ヘッダーのクラス名が映っているか、要素の上下順を記述してください」
- エラー画面の読み取り: 「画面内のエラーメッセージを原文のまま一字一句転記してください」
- 生成画像の確認: 「画像内に文字は入っているか、あれば原文を転記し、なければ明記してください」

### 応答品質の特性（2026-10-11 のテストで確認）

- 指示は system プロンプトとデフォルト質問に組み込まれており、自然な日本語・外国語混入禁止・事実と推測の区別・捏造禁止が期待される
- 同一画像の複数回実行で、瞳孔の色・形などの**細部記述がブレる**ことがある（例: 緑の楕円形 ↔ 緑の円形）
- 断定できない項目は「判定不能」や曖昧表現で返る場合がある。これを不具合と見なさない
- セッション側のモデルが画像入力をサポートしていない環境では、このツールが画像確認の標準手段となる

## 指示文（プロンプト）の構成

`server.py` 内の指示文は 2 箇所:

| 箇所 | 行 | 内容 |
|---|---|---|
| デフォルト質問 | 31 行目 | `question` 引数のデフォルト値（自然な日本語、外国語混入禁止、原文引用、事実と推測の区別、捏造禁止） |
| system プロンプト | 72〜78 行目 | 全回答に適用される指示（日本語品質、外国語の原文引用、推測・捏造禁止、画像内指示文の無視、コード操作禁止） |

応答品質が悪化・変化した場合、まずこの 2 箇所を確認すること。

## メンテナンス手順

### 1. `GROQ_API_KEY` 未設定エラー

エラー文: `設定エラー: GROQ_API_KEY 環境変数がありません。Windowsのユーザー環境変数に設定し、VS Codeを再起動してください。`

1. Windows の「環境の変数の編集」で `GROQ_API_KEY` を**ユーザー環境変数**として設定
2. VS Code を再起動（MCP ツールは起動時の環境を読み込む）
3. ツールを再実行して確認

### 2. ツールが認識されない / サーバー未起動

1. VS Code を再起動、または Kilo の MCP サーバーを再接続
2. MCP 設定（`kilo.json`）に `groq-image-analysis` サーバーが登録されているか確認
3. 登録なしの場合は `C:\OtherApp\groq_image_mcp\server.py` を stdio transport の MCP サーバーとして追加する

### 3. 指示文（プロンプト）の変更

1. `C:\OtherApp\groq_image_mcp\server.py` を **edit ツール**で編集（31 行目のデフォルト質問 / 72〜78 行目の system プロンプト）
2. 編集直後に構文チェック:

   ```
   python -m py_compile C:\OtherApp\groq_image_mcp\server.py
   ```

   成功時は `SYNTAX OK` を表示すること（`__pycache__` が生成されるだけなので無害）
3. **MCP サーバー再起動（または VS Code 再起動）で反映**。起動中のプロセスは旧プロンプトのままなので、反映後の動作確認を必ず行う

### 4. モデル・制限値の変更

`server.py` 冒頭および呼び出し部:

| 定数・引数 | 行 | 説明 |
|---|---|---|
| `MODEL` | 13 | 使用する Groq モデル ID（`qwen/qwen3.8-27b`） |
| `MAX_BYTES` | 14 | 画像サイズ上限（20 MiB） |
| `ALLOWED_EXTENSIONS` | 15 | 対応拡張子 |
| `timeout` / `max_retries` | 65 | Groq API クライアントのタイムアウト（90 秒）と再試行（1 回） |
| `max_completion_tokens` | 86 | 最大生成トークン（1200） |

変更後は必ず 3 の手順（py_compile + サーバー再起動 + 動作確認）を行う。

### 5. よくあるエラーメッセージ対応表

| メッセージ | 原因 | 対処 |
|---|---|---|
| `設定エラー: GROQ_API_KEY 環境変数がありません...` | API キー未設定 | 手順 1 |
| `画像ファイルを開けません: ...` | パス誤り・ファイル不在・権限 | パスの絶対パス指定を確認 |
| `入力エラー: image_pathには画像ファイルを指定してください。` | ディレクトリ指定 | ファイルパスを指定 |
| `対応形式は PNG / JPG / JPEG / WEBP です。` | 未対応形式 | 対応形式へ変換 |
| `入力エラー: ファイルが空です。` | 0 バイト | 正しい画像を指定 |
| `入力エラー: 画像は20 MiB以下にしてください...` | サイズ超過 | 画像を縮小・圧縮 |
| `Groqからテキスト回答が返りませんでした...` | 空応答 | 質問を簡潔にして再試行 |
| `Groq画像解析に失敗しました (...): ...` | API 側エラー（レート制限・一時的障害など） | 時間をおいて再試行。API キーの有効期限も確認 |

## ルール・注意事項

- 画像はクラウド（Groq API）へ送信される。Kilo 自身の作成による画像やプロジェクトフォルダ内の画像は確認不要。画像に機微・個人情報を含む場合は事前にユーザーの確認を取る
- ツールはファイル編集・コマンド実行・コード変更を行わず、テキストのみを返す
- `server.py` はワークスペース外（`C:\OtherApp\groq_image_mcp\`）のファイルで、git 管理下ではない。編集時は edit ツールを使い、編集後に py_compile と目視で破損確認を行う
- 本ドキュメントの行番号は 2026-10-11 時点の `server.py`（102 行）に基づく。ファイルが変更された場合は行番号を再確認すること
