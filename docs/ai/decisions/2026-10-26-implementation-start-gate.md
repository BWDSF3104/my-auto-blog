# 実装開始ゲート ルールの AGENTS.md 追加 — 最終

**Status**: 最終 (2026-10-26)
**Date**: 2026-10-26
**関連タスク**: `docs/ai/tasks/2026-10-26-implementation-start-gate.md`

## 要件（ユーザー、2026-10-26）

1. 明示的な実装開始指示を受けなければ、決して実装・ファイル変更を行わない
2. 除外: タスクファイルなどの「記録」更新
3. 例外: 設計〜実装を一任した場合は、別途の実装開始指示は不要

## 決定

AGENTS.md の `## 言語` の後、トップレベルに新セクション「実装開始ゲート」を追加:

```markdown
## 実装開始ゲート

- 明示的な実装開始指示を受けなければ、決して実装・ファイル変更を行わない。
  - 「実装」に含む除外: タスクファイル、decisions、`current-task.tsv`、`backlog.md`、known-issues、memory bank 等の「記録」更新。
  - 例外: ユーザーが設計〜実装を一任した場合は、別途の実装開始指示は不要。
  - 「明示的な実装開始指示」: 合意した設計の実装着手を示すユーザーの明らかな言葉（例: 「実装を開始して」「実装して」）。
```

## 根拠

- 設計先行フロー（`decisions/` への事前記録、commit/push の事前承認前提）は事実上は存在したが、「実装着手のタイミング」を規定するルールが欠けていた。agent が設計合意前に単独で実装へ進むリスクを排除する
- 記録除外により、`task_manager.py add`/`end`、memory bank、known-issues 等の記録フェーズには影響しない
- 「設計〜実装の一任」例外により、小規模な単発依頼への追加ラウンドトリップの増加を抑制

## 採用しない代替案

- `## ワークフロー` 内の記述 — 可視性が低いため非推奨
- 義務ではなく「推奨」の文言 — ユーザーの「決して」の意図に反するため不採用

## 影響

- 変更: AGENTS.md（新セクション）、決定的判断記録、タスクファイル、tsv（旧タスク Status 進行中 → 保留）。pytest / build 不要（docs/ai/ と AGENTS.md のみ変更の例外）
- 今後は、実装を伴うタスクにおいて、実装開始指示が実装開始の条件となる
