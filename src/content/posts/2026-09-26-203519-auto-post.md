## 概要と背景

大規模言語モデル（LLM）の知識を外部データベースで補強する **RAG（Retrieval-Augmented Generation）** は、エンタープライズAIアプリケーションのデファクトスタンダードとなりました。しかし、標準的な「ナイーブRAG（検索→生成）」には致命的な弱点が存在します。

1. **サイレント・ハルシネーション**: ベクトル検索がユーザーの意図と無関係なドキュメントを取得した場合でも、LLMはそのまま不正確な情報を基に回答を生成してしまう。
2. **不完全な情報源への依存**: 社内ナレッジベースに必要な回答が存在しない場合、誤った回答を出力するか「分かりません」と一律に拒否するしか選択肢がない。
3. **一発勝負（Single-pass）の限界**: 検索クエリのチューニングや情報の不備に対する自己修正ループが存在しない。

これらの課題を解決するために登場したのが、**Self-RAG** と **Corrective RAG (CRAG)** という2つの先進的な論文・手法です。本稿では、これら2つのアプローチを融合させ、検索結果の質をLLM自身が段階的に評価・修正し、必要に応じてWeb検索やクエリ再ライティング（Query Rewriting）へ動的に分岐する**「自己修復型RAG（Self-Corrective RAG）」**のメカニズムと実装方法を解説します。

## 技術的メカニズム・特徴

自己修復型RAGは、一方向のパイプラインではなく、**評価とフィードバックループを持つ状態遷移グラフ（State Graph）** として動作します。

```
[ユーザーの質問]
       │
       ▼
[ベクトル検索 (Retriever)]
       │
       ▼
[ドキュメント評価 (Document Evaluator)] ◄─── (関連性チェック)
       │
       ├───────────────────────────────┐
       ▼ (関連性: 高)                   ▼ (関連性: 低 / 不足)
[回答生成 (Generator)]             [クエリ再ライティング (Query Rewriter)]
       │                               │
       ▼                               ▼
[生成結果の自己検証]                 [Web検索フォールバック (Web Search)]
 (Self-Correction/Hallucination Check) │
       │                               │
       └───────────────────────────────┘
```

### 1. Self-RAG (Self-Reflective RAG)
Self-RAGは、生成プロセスの各段階でモデルが「リフレクション・トークン（Self-Reflection Tokens）」を出力し、自身の出力をメタ制御するフレームワークです。
- `Retrieve`: 外部知識の検索が必要か判定する
- `ISREL (Is Relevant)`: 取得したドキュメントが質問に関連しているか判定する
- `ISSUP (Is Supported)`: 生成された回答が取得ドキュメントの根拠に基づいているか判定する（ハルシネーションチェック）

### 2. Corrective RAG (CRAG)
CRAGは、検索エンジンの精度補正に特化した手法です。取得したドキュメントセットに対して信頼度スコアを算出し、以下の3つの動作に分岐します。
- **Correct（高信頼）**: 取得ドキュメントをそのまま採用し、ナレッジの絞り込み（Knowledge Refinement）を行って生成へ回す。
- **Incorrect（低信頼）**: ナレッジベースに十分な情報がないとみなし、外部Web検索API（TavilyやDuckDuckGoなど）へフォールバックする。
- **Ambiguous（曖昧）**: ナレッジベースの情報とWeb検索の結果を統合してコンテキストを補強する。

### 3. 両者を統合したワークフロー
本アーキテクチャでは、**LangGraph** を用いて状態を管理し、非同期かつ非線形な評価ループを構築します。
1. **Retrieve**: ベクトルデータベースから初期ドキュメントを取得。
2. **Grade Documents**: LLMが取得した各ドキュメントの関連性を二値判定（Yes/No）。
3. **Decide Route**: 
   - 全てのドキュメントが無関係なら ➔ **Transform Query** して Web検索へ。
   - 関連ドキュメントが存在するなら ➔ **Generate** へ。
4. **Grade Generation**: 生成された回答にハルシネーションがないか、また質問に対する直接的な回答になっているかを評価。不合格の場合はクエリを再ライティングしてルーティングを再実行。

### 2. パイプラインの実装コード

```python
import os
from typing import List, Literal, TypedDict
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.pydantic_v1 import BaseModel, Field
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langgraph.graph import END, StateGraph

# APIキーの設定（環境変数から取得することを推奨）
os.environ["OPENAI_API_KEY"] = "your-openai-api-key"
os.environ["TAVILY_API_KEY"] = "your-tavily-api-key"

# ---------------------------------------------------------------------------
# 1. 状態（State）の定義
# ---------------------------------------------------------------------------
class GraphState(TypedDict):
    question: str
    generation: str
    web_search_needed: bool
    documents: List[str]
    retry_count: int

# ---------------------------------------------------------------------------
# 2. 評価用データ構造（Pydantic Schemas）
# ---------------------------------------------------------------------------
class GradeDocuments(BaseModel):
    """取得したドキュメントが質問に関連しているかを評価するスコア"""
    binary_score: str = Field(
        description="ドキュメントが質問に関連している場合は 'yes'、そうでない場合は 'no'"
    )

class GradeHallucination(BaseModel):
    """回答がドキュメントに基づいているか（ハルシネーションがないか）の評価"""
    binary_score: str = Field(
        description="回答がドキュメントに裏付けられている場合は 'yes'、そうでない場合は 'no'"
    )

class GradeAnswer(BaseModel):
    """回答が質問に対して直接答えているかの評価"""
    binary_score: str = Field(
        description="回答が質問に適切に答えている場合は 'yes'、そうでない場合は 'no'"
    )

# ---------------------------------------------------------------------------
# 3. 各ノード（処理プロセッサ）の定義
# ---------------------------------------------------------------------------
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

def retrieve_node(state: GraphState):
    """ベクトルストアからドキュメントを取得（デモ用にダミーデータを返却）"""
    print("--- [NODE] 検索実行 (Retrieve) ---")
    question = state["question"]
    
    # 実際の実装ではここで Chroma や Pinecone などの VectorStore から search() を行う
    # ここでは概念を示すための模擬コンテキストを設定
    documents = [
        "当社の次世代AIプラットフォーム『Project Orion』は、完全オンプレミス環境での動作に対応しています。",
        "Project Orionの最小システム要件は、NVIDIA A100 GPU (80GB) 2枚以上、メモリ128GBです。"
    ]
    return {"documents": documents, "question": question, "retry_count": state.get("retry_count", 0)}

def grade_documents_node(state: GraphState):
    """ドキュメントの関連性を判別（Self-RAG / CRAG 判定）"""
    print("--- [NODE] ドキュメント適合性評価 (Grade Documents) ---")
    question = state["question"]
    documents = state["documents"]
    
    structured_llm = llm.with_structured_output(GradeDocuments)
    system_prompt = (
        "あなたはドキュメントとユーザーの質問との関連性を評価する審査官です。\n"
        "ドキュメントが質問に関連するキーワードまたは意味を含んでいる場合は 'yes'、それ以外は 'no' と判定してください。"
    )
    grade_prompt = ChatPromptTemplate.from_messages([
        ("system", system_prompt),
        ("human", "ドキュメント:\n{document}\n\n質問: {question}")
    ])
    evaluator = grade_prompt | structured_llm

    filtered_docs = []
    web_search_needed = False

    for doc in documents:
        res = evaluator.invoke({"document": doc, "question": question})
        if res.binary_score.lower() == "yes":
            print("  -> 適合ドキュメントを発見")
            filtered_docs.append(doc)
        else:
            print("  -> 不適合ドキュメントを除外")
    
    # 関連ドキュメントが1つもない場合はWeb検索フラグを立てる
    if len(filtered_docs) == 0:
        web_search_needed = True

    return {"documents": filtered_docs, "question": question, "web_search_needed": web_search_needed}

def transform_query_node(state: GraphState):
    """検索に失敗した場合、質問を再ライティングする (CRAG)"""
    print("--- [NODE] クエリ再ライティング (Transform Query) ---")
    question = state["question"]
    
    system_prompt = (
        "あなたは検索クエリの最適化専門家です。\n"
        "入力された質問を分析し、Web検索エンジンでより精度の高い結果が得られるように、意図を保持したまま最適な検索クエリに変換してください。"
    )
    re_write_prompt = ChatPromptTemplate.from_messages([
        ("system", system_prompt),
        ("human", "初期質問: {question}\n改善された検索クエリを出力してください。")
    ])
    
    query_rewriter = re_write_prompt | llm
    better_question = query_rewriter.invoke({"question": question}).content
    print(f"  -> 再構成クエリ: '{better_question}'")
    
    return {"question": better_question, "retry_count": state.get("retry_count", 0) + 1}

def web_search_node(state: GraphState):
    """Web検索による情報の代替取得（フォールバック処理）"""
    print("--- [NODE] Web検索フォールバック (Web Search) ---")
    from langchain_community.tools import TavilySearchResults
    
    question = state["question"]
    documents = state.get("documents", [])
    
    # Tavily検索の模擬実行 (APIキー未設定時のフォールバック処理含む)
    try:
        web_search_tool = TavilySearchResults(k_results=2)
        docs = web_search_tool.invoke({"query": question})
        web_results = "\n".join([d["content"] for d in docs])
    except Exception:
        web_results = f"Web検索結果（模擬）: '{question}' に関する最新の情報では、AWSおよびAzureでのクラウドデプロイもサポートされています。"

    documents.append(web_results)
    return {"documents": documents, "question": question}

def generate_node(state: GraphState):
    """検証済みコンテキストから回答を生成"""
    print("--- [NODE] 回答生成 (Generate) ---")
    question = state["question"]
    documents = state["documents"]
    
    gen_prompt = ChatPromptTemplate.from_messages([
        ("system", "あなたは与えられたコンテキストのみに基づいて誠実に回答するアシスタントです。"),
        ("human", "コンテキスト:\n{context}\n\n質問: {question}\n回答:")
    ])
    
    rag_chain = gen_prompt | llm
    context = "\n\n".join(documents)
    generation = rag_chain.invoke({"context": context, "question": question}).content
    return {"generation": generation, "question": question, "documents": documents}

# ---------------------------------------------------------------------------
# 4. 条件付きエッジ（ルーティング論理）の定義
# ---------------------------------------------------------------------------
def decide_to_generate(state: GraphState) -> Literal["transform_query", "generate"]:
    """ドキュメント評価結果に基づいて分岐"""
    if state["web_search_needed"]:
        print("--- [ROUTER] 適合ドキュメントなし -> クエリ再作成 & Web検索へ ---")
        return "transform_query"
    else:
        print("--- [ROUTER] 適合ドキュメントあり -> 回答生成へ ---")
        return "generate"

def grade_generation_v_documents_and_question(state: GraphState) -> Literal["useful", "not useful", "max_retries"]:
    """回答の自己検閲 (Self-RAG: ハルシネーションチェック & 質問充足度チェック)"""
    print("--- [ROUTER] 生成回答の検証 (Self-Correction) ---")
    question = state["question"]
    documents = state["documents"]
    generation = state["generation"]
    retry_count = state.get("retry_count", 0)

    if retry_count >= 2:
        print("--- [ROUTER] リトライ上限に達したため終了 ---")
        return "max_retries"

    # 1. ハルシネーション評価
    hallucination_grader = llm.with_structured_output(GradeHallucination)
    hal_prompt = ChatPromptTemplate.from_messages([
        ("system", "回答が提供されたドキュメントの事実に忠実であるかを判定してください。"),
        ("human", "ドキュメント:\n{documents}\n\n生成された回答:\n{generation}")
    ])
    is_supported = (hal_prompt | hallucination_grader).invoke({"documents": documents, "generation": generation})

    if is_supported.binary_score.lower() == "yes":
        print("  -> 検証Pass: ハルシネーションは検出されませんでした。")
        # 2. 質問に対する直接回答チェック
        answer_grader = llm.with_structured_output(GradeAnswer)
        ans_prompt = ChatPromptTemplate.from_messages([
            ("system", "回答が質問に明確かつ直接答えているかを判定してください。"),
            ("human", "質問:\n{question}\n\n生成された回答:\n{generation}")
        ])
        is_answer = (ans_prompt | answer_grader).invoke({"question": question, "generation": generation})
        
        if is_answer.binary_score.lower() == "yes":
            print("  -> 検証Pass: 質問への回答として適切です。")
            return "useful"
        else:
            print("  -> 検証Fail: 質問に対して不十分な回答です。")
            return "not useful"
    else:
        print("  -> 検証Fail: ハルシネーションが検出されました。")
        return "not useful"

# ---------------------------------------------------------------------------
# 5. LangGraph の構築とコンパイル
# ---------------------------------------------------------------------------
workflow = StateGraph(GraphState)

# ノードの追加
workflow.add_node("retrieve", retrieve_node)
workflow.add_node("grade_documents", grade_documents_node)
workflow.add_node("generate", generate_node)
workflow.add_node("transform_query", transform_query_node)
workflow.add_node("web_search", web_search_node)

# エッジ（接続）の構築
workflow.set_entry_point("retrieve")
workflow.add_edge("retrieve", "grade_documents")

workflow.add_conditional_edges(
    "grade_documents",
    decide_to_generate,
    {
        "transform_query": "transform_query",
        "generate": "generate",
    },
)

workflow.add_edge("transform_query", "web_search")
workflow.add_edge("web_search", "generate")

workflow.add_conditional_edges(
    "generate",
    grade_generation_v_documents_and_question,
    {
        "useful": END,
        "not useful": "transform_query",
        "max_retries": END,
    },
)

app = workflow.compile()

# ---------------------------------------------------------------------------
# 6. 実行テスト
# ---------------------------------------------------------------------------
if __name__ == "__main__":
    # ケース1: 社内ドキュメントで回答可能な質問
    print("\n==== Test Case 1: ナレッジベース内で解決可能な質問 ====")
    input_1 = {"question": "Project Orionの動作に必要な動作要件（GPU）を教えてください。"}
    for output in app.stream(input_1):
        pass

    # ケース2: 社内ドキュメントに存在しない質問（Web検索へフォールバック）
    print("\n==== Test Case 2: ナレッジベース外の質問 (CRAGフォールバック) ====")
    input_2 = {"question": "Project OrionはAWSで動作しますか？"}
    for output in app.stream(input_2):
        pass
```

## まとめ

### 従来のRAGと自己修復型RAGの比較

| 評価項目 | 従来のナイーブRAG | 自己修復型RAG (Self-RAG + CRAG) |
| :--- | :--- | :--- |
| **アーキテクチャ** | 単方向パイプライン (DAG) | 状態遷移グラフ（ループ・分岐構造） |
| **検索失敗時の挙動** | 無関係なコンテキストのまま強制生成 | クエリ再生成 ➔ Web検索へフォールバック |
| **ハルシネーション対策** | システムプロンプトによる指示のみ | LLMによる事後自己検証と自動やり直し |
| **信頼性・精度** | 検索精度に依存（低〜中） | 高い（厳格なフィルタリングと検証） |
| **応答レイテンシ** | 高速 (1回の推論) | 中程度（評価・ループ処理によるオーバーヘッドあり） |

### 今後の展望と適用シナリオ

本手法で解説した **Corrective RAG (CRAG)** と **Self-RAG** の統合アーキテクチャは、ミッションクリティカルなエンタープライズ製品（法務契約チェックシステム、医療ガイドライン照会、金融ドキュメント解析など）において、誤情報の許容率を極限まで下げるために不可欠な設計パターンです。

推論レイテンシを削減するためには、評価ノード（`Grade Documents` や `Grade Hallucination` など）に蒸留された小規模・高速なLLM（例: Llama-3.1-8BやGemma-2B）を割り当て、最終回答生成ノードにのみ大規模モデル（GPT-4oやClaude 3.5 Sonnet）を使用する**マルチモデルハイブリッド構成**をとることが、実稼働環境におけるベストプラクティスとなります。
