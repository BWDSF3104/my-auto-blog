# Model Context Protocol (MCP) 実践入門：AIエージェントとWebアプリを接続する新標準

## はじめに

大規模言語モデル（LLM）を実務に組み込む際、最大のボトルネックとなっていたのが「外部リソースやツールとの接続」です。従来のFunction CallingやAPI連携では、サービスごとに独自の実装やスキーマ定義が必要であり、接続先が増えるたびにコードのサイロ化と保守コストの増大が課題となっていました。

この課題を解決するオープン標準として注目を集めているのが、Anthropic社が提唱した**Model Context Protocol (MCP)**です。MCPは、AIモデルと外部データソース・ツールをつなぐプロトコルを「USB Type-C」のように統一し、一度開発したツールをさまざまなクライアント（Claude Desktop、独自のWebアプリ、社内エージェントなど）から共通で呼び出せるエコシステムを実現します。

本記事では、MCPのアーキテクチャ概要とともに、TypeScriptを用いたシンプルなMCPサーバーの実装手順とWebアプリケーションへの組み込み方を解説します。

## 詳細解説

### 1. MCPのコアアーキテクチャ

MCPはクライアント・サーバー型の設計を採用しており、主に以下の3つのコンポーネントで構成されます。

1. **MCP Host**: AIモデルを駆動し、ユーザーと対話する大元のアプリケーション（例: Claude Desktop、Web上のチャットUI）。
2. **MCP Client**: Hostの内部で動作し、各MCP Serverとの接続やメッセージルーティングを担当するクライアント層。
3. **MCP Server**: データベースアクセス、外部API呼び出し、ローカルファイル操作などの具体的な機能やデータを公開するプログラム。

MCPが提供する主要なプリミティブは以下の3点です。

- **Resources**: ドキュメントやDBレコードなど、モデルが参照するためのコンテキスト（データ）。
- **Prompts**: 再利用可能なプロンプトテンプレート。
- **Tools**: モデルが呼び出せる関数・実行可能コード（従来のツール呼び出しに相当）。

### 2. TypeScriptによるMCPサーバーの実装

公式のSDK (`@modelcontextprotocol/sdk`) を使用して、Web検索や社内データベースへの問い合わせを模した軽量なMCPサーバーを構築してみましょう。

#### プロジェクトの初期設定

```bash
mkdir mcp-weather-server
cd mcp-weather-server
npm init -y
npm install @modelcontextprotocol/sdk zod
npm install -D typescript @types/node tsx
npx tsc --init
```

#### サーバーコードの実装 (`src/index.ts`)

以下は、特定都市の天気を取得するツールを公開するMCPサーバーの実装例です。通信トランスポートには標準入出力（Stdio）を使用します。

```typescript
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";
import { z } from "zod";

// サーバーの初期化
const server = new Server(
  {
    name: "weather-service",
    version: "1.0.0",
  },
  {
    capabilities: {
      tools: {},
    },
  }
);

// ツールスキーマのバリデーション定義
const WeatherParamsSchema = z.object({
  city: z.string().describe("天気を取得したい都市名（例: Tokyo）"),
});

// 公開するツールの定義
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: "get_weather",
        description: "指定された都市の現在の天候情報を返します。",
        inputSchema: {
          type: "object",
          properties: {
            city: {
              type: "string",
              description: "都市名",
            },
          },
          required: ["city"],
        },
      },
    ],
  };
});

// ツールの実行ハンドラー
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name !== "get_weather") {
    throw new Error(`Unknown tool: ${request.params.name}`);
  }

  const { city } = WeatherParamsSchema.parse(request.params.arguments);

  // 実際のシステムでは外部API等を呼び出す
  const mockWeatherData = {
    Tokyo: "晴れ、気温 22℃",
    London: "雨、気温 14℃",
    "New York": "曇り、気温 18℃",
  };

  const weather = mockWeatherData[city as keyof typeof mockWeatherData] ?? "天候データが見つかりませんでした";

  return {
    content: [
      {
        type: "text",
        text: `【${city}の天候】: ${weather}`,
      },
    ],
  };
});

// 標準入出力トランスポートでサーバーを起動
async function main() {
  const transport = new StdioServerTransport();
  await server.connect(transport);
  console.error("Weather MCP Server running on stdio");
}

main().catch((error) => {
  console.error("Fatal error:", error);
  process.exit(1);
});
```

### 3. Webアプリケーション側のメリットと連携

MCPを導入することで、フロントエンドおよびバックエンド開発に以下のメリットが生まれます。

- **ポータビリティの向上**:
  一度作成したMCPサーバーは、Webアプリケーションのバックエンド（SSEトランスポート利用）としても、ローカル開発環境のClaude Desktopからも同一仕様で呼び出せます。
- **セキュリティの境界設定**:
  AIモデルに直接データベースや認証トークンを露出させることなく、MCPサーバーが権限管理のゲートウェイとして機能します。
- **疎結合なマイクロサービス化**:
  「社内GitHub検索用MCP」「Notion同期用MCP」「デプロイ実行MCP」といった単位で独立したサーバーとして開発・管理が可能です。

## まとめ

Model Context Protocol (MCP) は、乱立していたLLMの外部連携仕様を統合し、AIアプリケーション開発を「単一のチャットUI構築」から「包括的なツール統合エコシステムの構築」へと昇華させました。

TypeScriptなどの標準的な言語スタックで容易にサーバーを実装できるため、既存のREST/GraphQL API資産をMCP化してエージェントへ提供するアプローチは、今後のWeb開発において不可欠なスキルとなるでしょう。まずは社内の共通APIやユーティリティをMCPサーバーとして切り出し、AIによるワークフロー自動化の第一歩を踏み出してみてください。
