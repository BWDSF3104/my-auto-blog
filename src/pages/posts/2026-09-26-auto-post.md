# MCP (Model Context Protocol) 入門：AIエージェントとWebシステムを安全に繋ぐ次世代標準の実践

## はじめに

大規模言語モデル（LLM）を活用したAIエージェントの開発において、外部のデータベースやWeb API、社内システムとの連携は不可欠な要素となっています。これまで、開発者は各LLMプロバイダーやフレームワークの仕様に合わせて個別にツール接続コード（Tool Calling / Function Calling）を実装する必要があり、エコシステムの分断と運用コストの増大が課題となっていました。

この課題を解決するオープン標準として登場したのが、Anthropicが提唱する **Model Context Protocol (MCP)** です。

MCPは、AIアシスタント（MCPクライアント）と、データソースやツール（MCPサーバー）を分離し、標準化されたプロトコル経由で安全に通信するための規約です。本記事では、MCPの基礎概念から、TypeScriptを用いたMCPサーバーの構築、既存Webアプリケーションとの連携方法までを具体的に解説します。

---

## 詳細解説

### 1. MCPの全体像とアーキテクチャ

MCPは、Web開発における **Client-Serverモデル** に着想を得たアーキテクチャを採用しています。

- **MCP Client（クライアント）**: Claude DesktopやCursorなどのAIアプリケーション、あるいは自作のエージェントシステム。ユーザーのリクエストに応じて、必要なMCPサーバーへリクエストを発行します。
- **MCP Server（サーバー）**: データベース、Web API、ファイルシステムなどのローカル/リモートリソースを抽象化し、プロトコルに従ってコンテキストやツール（関数）を提供します。
- **Transport（トランスポート層）**: ClientとServer間の通信を担います。ローカル環境では `stdio`（標準入出力）、リモート環境では `SSE`（Server-Sent Events）やHTTP/WebSocketが利用されます。

```
[ LLM / AI App ]
       │
       ▼ (MCP Client)
 ┌───────────────┐
 │   MCP Transport (stdio / SSE)
 └───────────────┘
       │
       ▼ (MCP Server)
┌────────────────────────────────┐
│  - Resources (データ・文書)     │
│  - Tools (実行可能な処理/API)   │
│  - Prompts (定型プロンプト)    │
└────────────────────────────────┘
```

MCPの導入により、一度開発したMCPサーバーは、プロトコルに対応する任意のAIクライアントから再利用可能になります。

### 2. TypeScriptによるMCPサーバーの構築

ここでは、Web開発で一般的な TypeScript を使い、既存のWeb APIからデータを取得してAIに提供するMCPサーバーを作成してみます。

#### 事前準備

公式SDKである `@modelcontextprotocol/sdk` と、スキーマ定義のための `zod` をインストールします。

```bash
npm install @modelcontextprotocol/sdk zod
npm install -D typescript @types/node
```

#### MCPサーバーの実装

以下は、外部の顧客管理API（CRM）から情報を取得し、AIエージェントに機能を提供するMCPサーバーの例です。

```typescript
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";
import { z } from "zod";

// 1. サーバーの初期化
const server = new Server(
  {
    name: "customer-api-server",
    version: "1.0.0",
  },
  {
    capabilities: {
      tools: {}, // ツール呼び出し機能を有効化
    },
  }
);

// 2. 提供するツールの定義（スキーマ定義）
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: "get_customer_info",
        description: "顧客IDを指定して、顧客の基本情報と契約ステータスを取得します。",
        inputSchema: {
          type: "object",
          properties: {
            customerId: {
              type: "string",
              description: "取得対象の顧客ID (例: CUST-1001)",
            },
          },
          required: ["customerId"],
        },
      },
    ],
  };
});

// 3. ツールの実行ハンドラーの実装
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  if (request.params.name === "get_customer_info") {
    const customerId = String(request.params.arguments?.customerId);

    try {
      // 本来はここで実際のWeb APIやDBへアクセスします
      const mockData = {
        id: customerId,
        name: "山田 太郎",
        plan: "Enterprise",
        status: "Active",
      };

      return {
        content: [
          {
            type: "text",
            text: JSON.stringify(mockData, null, 2),
          },
        ],
      };
    } catch (error) {
      return {
        isError: true,
        content: [
          {
            type: "text",
            text: `顧客情報の取得に失敗しました: ${(error as Error).message}`,
          },
        ],
      };
    }
  }

  throw new Error(`不明なツールです: ${request.params.name}`);
});

// 4. トランスポートの接続と起動
async function main() {
  const transport = new StdioServerTransport();
  await server.connect(transport);
  console.error("MCP Server is running on stdio...");
}

main().catch((error) => {
  console.error("Fatal error:", error);
  process.exit(1);
});
```

### 3. MCPを導入するメリットと設計上の考慮点

#### 主なメリット
1. **相互運用性の向上**: 1つのMCPサーバーを書けば、Claude Desktop、Cursor、独自構築のLangChainエージェントなど、多様なクライアントから即座に利用可能。
2. **セキュリティとアクセスコントロール**: LLMに対してデータベースの直接参照を許可するのではなく、MCPサーバー側でバリデーションや認可ロジックを挟むことで安全性を確保。
3. **関心の分離**: AIプロンプトの調整と、外部データへの接続API実装を完全に独立して設計可能。

#### 設計時の注意点
- **入力値の厳格な検証**: LLMが生成する引数は不確実性を含むため、`zod` などを用いて厳密に引数のバリデーションを行ってください。
- **エラーハンドリング**: API制限やネットワークエラーが発生した際、AI側が適切にリトライや代替案を提示できるよう、エラーレスポンスのメッセージを明確に構築することが重要です。

## まとめ

Model Context Protocol (MCP) は、複雑化するAIエージェント開発において、データ連携とツール呼び出しの基盤を共通化する重要な標準規格です。

従来の自作Function Calling実装からMCPベースのアーキテクチャへ移行することで、コードの再利用性が飛躍的に向上し、セキュリティ面でも堅牢なAI連携アプリケーションを構築できます。今後、主要なSaaSやデータベースツールがMCP対応を進めることで、Web開発者にとっても必須の技術スタックとなっていくでしょう。まずはローカル環境で小さなMCPサーバーを作成し、開発ワークフローへの組み込みを試してみてください。
