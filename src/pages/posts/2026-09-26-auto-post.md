# WebGPUとTransformers.js v3で実現する「完全ブラウザ完結型」クライアントサイドAI実践

## はじめに

これまで、Webアプリケーションに機械学習モデルや生成AIを組み込む際、バックエンドに配置したAPIサーバー（OpenAI APIや独自ホストのPythonサーバーなど）を経由させる構成が一般的でした。しかし、このアーキテクチャには以下の課題が常に付きまといます。

1. **インフラコストの増大**: ユーザー数やリクエスト数に比例してGPUサーバー費用やトークン課金が膨らむ
2. **レイテンシの発生**: ネットワーク往復遅延が生じる
3. **プライバシーとセキュリティ**: 機密データや個人情報を外部サーバーへ送信する必要がある

近年、主要ブラウザで**WebGPU**が標準サポートされ、ONNX Runtime Webなどの基盤技術が急速に成熟したことで、**「ユーザーの端末のGPUを活用し、ブラウザ内で直接モデルを推論させる」**という選択肢が現実的になりました。

本記事では、ブラウザで機械学習パイプラインを簡潔に実装できるライブラリ「**Transformers.js v3**」とWebGPUを組み合わせ、サーバー不要で動作するクライアントサイドAI機能を構築する手法を詳しく解説します。

---

## 詳細解説

### 1. なぜ今クライアントサイドAIなのか？

クライアントサイド推論は、単なる「サーバーレス化」にとどまらず、新しいUXの価値を提供します。

- **ゼロ・ランニングコスト**: 推論はユーザーのデバイス資源で行われるため、サービス運営者側の推論コストはゼロになります。
- **オフライン動作**: 一度モデルキャッシュが完了すれば、PWA（Progressive Web Apps）などと組み合わせて電波の届かない環境でもAI機能が動きます。
- **データプライバシーの担保**: 入力テキストや音声、画像データが外部サーバーに送信されないため、医療・法務・社内ツールなどのセンシティブなユースケースに最適です。

Transformers.js v3では、Hugging Faceのエコシステムと直結しており、テキスト分類、固有表現抽出（NER）、画像認識、文字起こし（Whisper）、さらには小型LLMのテキスト生成まで、Python版とほぼ同様のAPIでブラウザから呼び出すことが可能です。

---

### 2. 環境セットアップと導入

まずは、現代的なフロントエンド環境（Vite + TypeScriptなど）へTransformers.jsを導入します。

```bash
npm install @huggingface/transformers
```

> **注意**: WebGPUを利用するには、ブラウザがWebGPU APIに対応している必要があります（Chrome, Edge, Safariなどの最新安定版）。

---

### 3. 実践コード：ブラウザ完結の感情分析パイプライン

ここでは、WebGPUアクセラレーションを有効にし、入力テキストの感情を分類する最小限の実装例を示します。

```typescript
import { pipeline } from '@huggingface/transformers';

async function runSentimentAnalysis() {
  const statusElement = document.getElementById('status')!;
  statusElement.textContent = 'モデルを読み込み中...（初回のみダウンロードが発生します）';

  // 1. WebGPUバックエンドを指定してパイプラインを初期化
  const classifier = await pipeline(
    'sentiment-analysis',
    'Xenova/distilbert-base-uncased-finetuned-sst-2-english',
    {
      device: 'webgpu', // 'webgpu' または 'wasm' (フォールバック用)
      dtype: 'fp32',    // 端末の対応状況に応じて 'fp16' や 'q8' (量子化) を指定可能
    }
  );

  statusElement.textContent = '推論実行中...';

  // 2. 推論の実行
  const text = "Transformers.js running directly on WebGPU is amazingly fast!";
  const output = await classifier(text);

  console.log(output);
  // 出力例: [{ label: 'POSITIVE', score: 0.9998 }]

  statusElement.textContent = `結果: ${output[0].label} (確信度: ${(output[0].score * 100).toFixed(2)}%)`;
}

runSentimentAnalysis();
```

### 4. 実戦投入における3つの重要ポイント

ブラウザ上でモデルを動かす場合、サーバーサイド開発とは異なる固有の課題が発生します。本番アプリケーションに組み込む際は、以下の3点に配慮してください。

#### ① Web Workerへのオフロード
AI推論は大量の計算リソースを消費するため、メインスレッド（UI描画スレッド）で実行すると画面のカクつきやフリーズの原因になります。パイプラインの生成と推論処理は、必ず**Web Worker**に移譲してバックグラウンドで実行し、結果を`postMessage`でメインスレッドに通知する設計を採用しましょう。

#### ② モデルキャッシュとプログレス表示
数十MBから数百MBあるモデルファイルは、ブラウザのCache API / IndexedDBに保存されます。初回の読み込みには時間がかかるため、Transformers.jsが提供する進捗コールバックを活用してプログレスバーを表示し、ユーザーに読み込み状況を可視化することが不可欠です。

```typescript
const classifier = await pipeline('sentiment-analysis', 'model-name', {
  progress_callback: (progressInfo) => {
    if (progressInfo.status === 'progress') {
      console.log(`ダウンロード進捗: ${progressInfo.progress.toFixed(1)}%`);
    }
  },
});
```

#### ③ 量子化（Quantization）モデルの積極的活用
メモリ帯域が限られるブラウザ環境では、8-bitや4-bitに量子化されたモデル（`q8`、`q4`形式）を採用することで、精度を保ちつつファイルサイズを半分以下に削減し、ダウンロード時間とVRAM消費を大幅に抑制できます。

## まとめ

WebGPUの標準化とTransformers.jsの登場によって、AI処理を「すべてサーバー側のAPIに投げる」時代から、「**センシティブな処理や即時性が求められるタスクはクライアントのブラウザ内で完結させる**」ハイブリッドな設計が選択できるようになりました。

すべてのユースケースをクライアントサイドで代替できるわけではありませんが、要約、翻訳、テキスト分類、音声認識などのタスクは、すでに一般的なノートPCやスマートフォンのブラウザで軽快に動作します。

「プライバシー保護」「ゼロ・サーバーコスト」「オフライン対応」という強力な強みを持つクライアントサイドAIを、ぜひ次世代のWebアプリケーション設計に取り入れてみてください。
