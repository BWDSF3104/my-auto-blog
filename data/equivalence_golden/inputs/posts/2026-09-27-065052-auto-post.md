## 概要と背景

大規模言語モデル（LLM）のスケール拡大に伴い、モデルのパラメータ数と計算コストは肥大化の一途を辿っています。特に推論フェーズにおけるメモリアクセス帯域（Memory Bandwidth）と浮動小数点演算（FP16/BF16などによるGEMM：General Matrix Multiplication）の電力消費は、エッジデバイスやクラウドインフラにおけるボトルネックとなっています。

これまでも Post-Training Quantization (PTQ) や Quantization-Aware Training (QAT) を用いた8bit (INT8) や 4bit (INT4) への低ビット量子化手法（GPTQ, AWQ等）が提案されてきました。しかし、これらは「既存の倍精度/半精度モデルを後から圧縮する」アプローチが多く、ビット数を極限まで落とすと著しい性能低下を引き起こす課題がありました。

この限界を打ち破るブレイクスルーとして登場したのが、1ビットLLMアーキテクチャ **BitNet**、およびその改良版である **BitNet b1.58**（1.58-bit Large Language Model）です。

BitNet b1.58は、モデルのすべての重み（Weights）を $\{-1, 0, 1\}$ の**3値（Ternary）**に制約して学習します。表現可能な状態数が $3$ であることから、情報理論上の必要ビット数は $\log_2(3) \approx 1.58$ ビットとなります。

最大の特徴は、**「重みとの積」が「要素の選択と加算/減算のみ」に置換される**点です。これにより、高コストな高精度浮動小数点積算器（Multiplier）を排除し、極めて低いエネルギーで高速な推論が可能となります。

```
[従来のLLM推論 (FP16/INT8)]
  Y = X × W  (高コストな浮動小数点/整数積算 GEMM)

[BitNet b1.58 推論]
  Y = X_quant × W_ternary  (積算器不要：符号判定と加算/減算のみ)
```

本稿では、BitNet b1.58の数理的メカニズム、エネルギー効率向上の背景、およびPyTorchによる量子化層（`BitLinear`）の具体的な実装までを詳細に解説します。

## 技術的メカニズム・特徴

### 1. 3値（Ternary）量子化とAbsMeanスケーリング

BitNet b1.58における重みの量子化は、**AbsMean（絶対値平均）スケーリング**に基づいています。

重み行列 $W \in \mathbb{R}^{n \times m}$ に対し、まず全体（またはチャネル単位）の絶対値平均 $\gamma$ を計算します。

$$\gamma = \frac{1}{n \times m} \sum_{i,j} |W_{i,j}|$$

このスケール因子 $\gamma$ を用いて重みを正規化し、最も近い整数 $\{-1, 0, 1\}$ に四捨五入（`round`）後、クリッピング処理を行います。

$$\tilde{W} = \text{Clip}\left( \text{Round}\left( \frac{W}{\gamma + \epsilon} \right), -1, 1 \right)$$

ここで $\text{Clip}(x, -1, 1) = \max(-1, \min(1, x))$ であり、$\epsilon$ はゼロ割りを防ぐ微小値です。

量子化された重み $\tilde{W}$ は、元のスケールに戻すための $\gamma$ とセットで保持されます。

```
元の重み (FP32/BF16): [ -0.82,  0.05,  0.91, -0.12 ]
                 ↓  (γ = 0.475 で正規化＆Round)
量子化重み (3値):     [   -2,     0,     2   ,   0  ] → Clip(-1, 1)
結果 (1.58-bit):      [   -1,     0,     1   ,   0  ]
```

### 2. アクティベーションのINT8量子化 (AbsMax Scaling)

重みだけでなく、入力アクティベーション $X$ も低ビット（通常はINT8、即ち $[-Q_b, Q_b-1]$ の範囲、ここで $Q_b = 2^{b-1} = 128$）に量子化します。

アクティベーションの量子化には **AbsMax（絶対値最大）スケーリング**が用いられます。

$$\eta = \max_{i,j} |X_{i,j}|$$

$$\tilde{X} = \text{Clip}\left( \text{Round}\left( X \times \frac{Q_b}{\eta} \right), -Q_b, Q_b - 1 \right)$$

順伝播の出力 $Y$ は、量子化されたテンソル同志の計算後にスケール因子を掛け合わせることで復元されます。

$$Y \approx (\tilde{X} \cdot \tilde{W}) \times \frac{\gamma \cdot \eta}{Q_b}$$

ここで最も重要なのは、**$\tilde{X} \cdot \tilde{W}$ の計算プロセス**です。$\tilde{W}_{i,j} \in \{-1, 0, 1\}$ であるため：
- $\tilde{W}_{i,j} = 1$ の場合：$\tilde{X}$ の値をそのまま**加算**
- $\tilde{W}_{i,j} = -1$ の場合：$\tilde{X}$ の値を**減算**
- $\tilde{W}_{i,j} = 0$ の場合：**計算をスキップ（または0）**

積算器（Multiplier）を使わず、加算器（Adder）のみで線形結合を計算可能になることが、BitNet b1.58の最大の優位性です。

### 3. Straight-Through Estimator (STE) による勾配伝播

`Round` や `Clip` 関数は至るところで微分係数が $0$ となる不連続関数（Step Function）であるため、通常の逆伝播では重みの更新ができません。

これに対処するため、学習時には **Straight-Through Estimator (STE)** を適用します。逆伝播時において、量子化関数の勾配を恒等関数（Identity）として直接スルーさせます。

$$\frac{\partial \text{Loss}}{\partial W} \approx \frac{\partial \text{Loss}}{\partial \tilde{W}}$$

学習中の潜在的な重み（Latent Weights）はFP32/BF16の連続値として保持され、順伝播時にのみオンザフライで3値化されます。

## 実装・活用コード例

以下は、PyTorchを用いて BitNet b1.58 の中核となる `BitLinear` 層を構築し、動的に3値量子化を行う完全な実装コードです。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class STEQuantizeTernary(torch.autograd.Function):
    """
    Straight-Through Estimator (STE) を用いた3値化 (-1, 0, 1) フック
    """
    @staticmethod
    def forward(ctx, weight):
        # 1. 重みの絶対値平均 gamma を算出
        gamma = torch.mean(torch.abs(weight))
        
        # 2. スケーリングと四捨五入
        scaled_weight = weight / (gamma + 1e-8)
        quantized = torch.clamp(torch.round(scaled_weight), min=-1, max=1)
        
        # スケール因子 gamma をコンテキストに保存（後段で使用可能）
        ctx.gamma = gamma
        return quantized, gamma

    @staticmethod
    def backward(ctx, grad_quantized, grad_gamma):
        # STE: 勾配をそのまま素通りさせる
        return grad_quantized


def quantize_activations_int8(x, num_bits=8):
    """
    アクティベーションを AbsMax スケーリングで INT8 に量子化
    """
    qmax = 2 ** (num_bits - 1) - 1  # 127
    gamma = torch.max(torch.abs(x), dim=-1, keepdim=True).values
    gamma = torch.clamp(gamma, min=1e-8)
    
    # スケーリング
    x_scaled = x * (qmax / gamma)
    x_quant = torch.clamp(torch.round(x_scaled), -qmax, qmax - 1)
    
    return x_quant, gamma / qmax


class BitLinear(nn.Module):
    """
    BitNet b1.58 のためのカスタム BitLinear 層
    """
    def __init__(self, in_features, out_features, bias=False):
        super().__init__()
        self.in_features = in_features
        self.out_features = out_features
        
        # 連続値の潜在的な重み (Latent Weight)
        self.weight = nn.Parameter(torch.Tensor(out_features, in_features))
        if bias:
            self.bias = nn.Parameter(torch.Tensor(out_features))
        else:
            self.register_parameter('bias', None)
            
        self.reset_parameters()

    def reset_parameters(self):
        # Xavier Normal 初期化
        nn.init.xavier_normal_(self.weight)
        if self.bias is not None:
            nn.init.zeros_(self.bias)

    def forward(self, x):
        # 1. 重みの3値化 (STE適用)
        w_quant, w_scale = STEQuantizeTernary.apply(self.weight)
        
        # 2. 入力アクティベーションの8bit量子化
        x_quant, x_scale = quantize_activations_int8(x)
        
        # 3. 擬似的な低精度行列積 (実際の実装では専用CUDAカーネルで加算処理を行う)
        # x_quant (INT8) x w_quant ({-1, 0, 1})
        y_int = F.linear(x_quant, w_quant)
        
        # 4. スケール因子の復元 (De-quantization)
        # y = y_int * x_scale * w_scale
        output = y_int * x_scale * w_scale
        
        if self.bias is not None:
            output += self.bias
            
        return output


# --- 動作検証・テストコード ---
if __name__ == "__main__":
    torch.manual_seed(42)

    batch_size = 2
    seq_len = 4
    d_in = 8
    d_out = 16

    # テスト入力テンソル (FP32)
    x = torch.randn(batch_size, seq_len, d_in)

    # BitLinear層のインスタンス化
    bit_linear = BitLinear(d_in, d_out)

    # 順伝播
    output = bit_linear(x)

    print("=== BitLinear 動作確認 ===")
    print(f"入力形状: {x.shape}")
    print(f"出力形状: {output.shape}")

    # 重みの量子化状態を確認
    w_quant, w_scale = STEQuantizeTernary.apply(bit_linear.weight)
    unique_elements = torch.unique(w_quant)
    print(f"量子化後の重みの固有値: {unique_elements.tolist()}")
    print(f"重みのスケール因子 (gamma): {w_scale.item():.6f}")

    # 逆伝播の動作テスト
    loss = output.sum()
    loss.backward()
    print(f"潜在重みの勾配が存在するか: {bit_linear.weight.grad is not None}")
    print(f"勾配ノルム: {bit_linear.weight.grad.norm().item():.6f}")
```

### コードの解説

1. **`STEQuantizeTernary`**: `torch.autograd.Function` を継承し、順伝播で AbsMean スケーリングによる $\{-1, 0, 1\}$ への3値化を実行します。逆伝播では `backward` で勾配をそのまま返すことでSTEを実現しています。
2. **`quantize_activations_int8`**: アクティベーションを行（トルク/トークン）ごとに AbsMax スケーリングし、INT8（$-128 \sim 127$）の範囲に収めます。
3. **`BitLinear` モジュール**: 学習時は内部で連続値の `weight` を保持しつつ、推論・順伝播の直前で $3$ 値に動的量子化します。専用のハードウェア/CUDAカーネル（例: `bitnet.cpp` など）と組み合わせることで、`F.linear` の内部処理を物理的な加算命令（`ADD` / `SUB`）へと置き換えることが可能です。

## まとめ

BitNet b1.58 は、単なる「モデル圧縮の手法」にとどまらず、**LLMの計算パラダイムそのものを「浮動小数点行列乗算」から「整数加算」へと変革する**革新的なアーキテクチャです。

### 本手法のインパクトとポイント

1. **行列乗算フリー（Addition-Only）な演算**:
   重みを $\{-1, 0, 1\}$ に限定することで、推論時のエネルギー消費量を大幅に削減（文献によれば、FP16比較で計算エネルギーを数十分の1に低減）。
2. **メモリアクセス帯域の劇的な改善**:
   重みを1.58ビットで保持できるため、メモリフットプリントが大幅に縮小。DRAMからSRAM/キャッシュへの転送ネックが解消し、推論のレイテンシとスループットが飛躍的に向上。
3. **Scaling Law（スケーリング法則）の維持**:
   従来の極端な1ビット量子化と異なり、BitNet b1.58 はモデルサイズを拡大した際に FP16 の標準Transformer（LLaMA等）と同等以上のパープレキシティ（Perplexity）を維持できることが実証されている。

今後は、専用の推論エンジン（C++実装やNPU最適化）の開発が進むことで、スマートフォンや車載チップなどのエッジデバイス上で、ギガバイトクラスのLLMを超低消費電力でローカル動作させる世界が現実のものとなっていきます。
