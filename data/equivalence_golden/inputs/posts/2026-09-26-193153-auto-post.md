## はじめに

チャットボットをはじめとする生成AIアプリケーションの多くは、依然としてMarkdown形式のプレーンテキストをストリーミング表示するUIが主流です。しかし、フライト予約、金融データの可視化、ECサイトの決済確認など、複雑なコンテキストを扱う場面において、テキストのみのインターフェースはユーザー体験のボトルネックになりつつあります。

この課題を打破するパラダイムが**Generative UI（生成的UI）**です。Generative UIでは、LLM（大規模言語モデル）の出力に応じて、テキストだけでなく最適化されたインタラクティブなReactコンポーネントを直接クライアントにストリーミング描画します。

本記事では、Next.js App Routerと**Vercel AI SDK（UI / RSCストリーミング）**を組み合わせ、LLMのツール呼び出し（Tool Calling）をトリガーにして動的コンポーネントをリアルタイム描画する実装パターンを詳しく解説します。

---

## 詳細解説

### 1. Generative UIの設計思想

従来のツール呼び出し（Function Calling / Tool Calling）では、AIが関数を実行して得たJSONデータをバックエンドでテキストに再変換してからユーザーへ返送するのが一般的でした。

Generative UIでは、LLMが「ツールを実行すべき」と判断した段階で、サーバーサイドでReactコンポーネントのレンダリングを開始し、そのコンポーネントツリーをServer-Sent Events（SSE）経由でクライアントへ直接ストリーミングします。

```
[User Request]
      │
      ▼
[LLM (Tool Calling)] ──> ツール実行 (例: 株価データ取得)
      │
      ▼
[React Server Component] ──> <StockCard data={...} /> を生成
      │ (Streaming)
      ▼
[Client UI] ──> グラフやボタンを含むリッチUIが即座に表示
```

これにより、ユーザーは静的なテキストを読まされることなく、ボタンのクリックや入力が可能な操作性の高いウィジェットを直接操作できます。

### 3. Server Actionsによるストリーミング実装

Next.jsのServer Actionsと`ai/rsc`モジュールの`streamUI`を活用し、ユーザーの入力に応じてテキストまたはコンポーネントをストリーミングするバックエンドロジックを構築します。

以下の例では、株価の問い合わせに対してリアルタイムチャート風のコンポーネント（`StockCard`）を返すツールを定義しています。

```tsx
// app/actions.tsx
'use server';

import { createAI, streamUI } from 'ai/rsc';
import { openai } from '@ai-sdk/openai';
import { z } from 'zod';

// モックの株価コンポーネント
function StockCard({ symbol, price, change }: { symbol: string; price: number; change: string }) {
  const isPositive = !change.startsWith('-');
  return (
    <div className="p-4 border rounded-xl shadow-sm bg-white max-w-sm my-2">
      <div className="text-sm font-semibold text-gray-500">{symbol}</div>
      <div className="text-2xl font-bold">${price.toFixed(2)}</div>
      <div className={`text-sm ${isPositive ? 'text-green-600' : 'text-red-600'}`}>
        {change}
      </div>
      <button 
        className="mt-3 w-full bg-blue-600 hover:bg-blue-700 text-white text-xs font-semibold py-1.5 px-3 rounded"
        onClick={() => alert(`${symbol} の詳細チャートを開きます`)}
      >
        詳細を分析
      </button>
    </div>
  );
}

// ユーザーメッセージ送信時に実行されるServer Action
export async function submitUserMessage(input: string) {
  'use server';

  const ui = await streamUI({
    model: openai('gpt-4o'),
    prompt: input,
    text: ({ content }) => <p className="text-gray-800 leading-relaxed">{content}</p>,
    tools: {
      showStockPrice: {
        description: '特定の銘柄の現在の株価情報をカード形式で表示する',
        parameters: z.object({
          symbol: z.string().describe('株式のティッカーシンボル (例: AAPL, TSLA)'),
        }),
        generate: async function* ({ symbol }) {
          // コンポーネント生成中のローディングスケルトンを先行返却
          yield (
            <div className="p-4 border rounded-xl animate-pulse bg-gray-50 max-w-sm my-2">
              <div className="h-4 bg-gray-200 rounded w-1/4 mb-2"></div>
              <div className="h-8 bg-gray-200 rounded w-1/2"></div>
            </div>
          );

          // 外部APIからのデータフェッチをシミュレート
          await new Promise((resolve) => setTimeout(resolve, 1000));
          const mockPrice = Math.random() * 200 + 100;
          const mockChange = (Math.random() * 10 - 5).toFixed(2) + '%';

          return <StockCard symbol={symbol.toUpperCase()} price={mockPrice} change={mockChange} />;
        },
      },
    },
  });

  return {
    id: Date.now(),
    role: 'assistant',
    display: ui.value,
  };
}
```

#### ポイント
1. **`yield` による段階的ストリーミング**: `generate`関数をジェネレーターとして実装することで、データ取得中の「スケルトンUI」を即時ストリーミングし、取得完了後に実データを含む「完成版UI」へ差し替えるスムーズなUXを実現できます。
2. **型安全なパラメータ定義**: `zod`スキーマを使用することで、LLMから渡される引数を型レベルでバリデーションし、不正なデータによる実行時エラーを防止します。

### 4. クライアント側のUI統合

クライアントサイドでは、通常のチャットUIのメッセージ配列にReactノード（`display`）をそのまま格納してレンダリングします。

```tsx
// app/page.tsx
'use client';

import { useState, ReactNode } from 'react';
import { submitUserMessage } from './actions';

interface ClientMessage {
  id: number;
  role: 'user' | 'assistant';
  display: ReactNode;
}

export default function ChatPage() {
  const [input, setInput] = useState('');
  const [conversation, setConversation] = useState<ClientMessage[]>([]);

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    if (!input.trim()) return;

    const userMessage: ClientMessage = {
      id: Date.now(),
      role: 'user',
      display: <div className="text-right font-medium text-blue-600 mb-2">{input}</div>,
    };

    setConversation((prev) => [...prev, userMessage]);
    setInput('');

    // Server Actionを呼び出してストリーミングUIを受信
    const response = await submitUserMessage(input);
    setConversation((prev) => [...prev, response]);
  };

  return (
    <div className="max-w-2xl mx-auto p-6">
      <h1 className="text-2xl font-bold mb-4">Generative UI Demo</h1>
      
      <div className="border rounded-lg p-4 min-h-[400px] mb-4 bg-gray-50 overflow-y-auto">
        {conversation.map((msg) => (
          <div key={msg.id} className="mb-4">
            {msg.display}
          </div>
        ))}
      </div>

      <form onSubmit={handleSubmit} className="flex gap-2">
        <input
          type="text"
          value={input}
          onChange={(e) => setInput(e.target.value)}
          placeholder="例: Appleの株価を教えて"
          className="flex-1 p-2 border rounded-md"
        />
        <button type="submit" className="bg-blue-600 text-white px-4 py-2 rounded-md hover:bg-blue-700">
          送信
        </button>
      </form>
    </div>
  );
}
```

### 5. Generative UI運用のベストプラクティス

1. **フォールバックとエラーハンドリング**
   LLMの引数生成失敗や外部APIのエラーに備え、`generate`関数内で`try-catch`を徹底し、エラー時にはリカバリー用のアクションボタンを含むエラーコンポーネントを返送する設計にします。

2. **クライアントコンポーネントとサーバーコンポーネントの分離**
   ストリーミングされるコンポーネント自体はサーバー側で生成されますが、インタラクティブな要素（状態管理、イベントハンドラーなど）を持たせる場合は、コンポーネント内部で`'use client'`ディレクティブを適切に定義した別モジュールをインポートして組み合わせます。

3. **セキュリティとコンポーネントインジェクション防止**
   AIが任意のHTMLや危険なスクリプトを直接出力するのではなく、**開発者が事前に安全を保証したホワイトリスト形式のコンポーネント**のみをツール経由で呼び出すアーキテクチャを厳格に維持します。

## まとめ

Generative UIは、従来の「テキストを読んで人間が解釈する」インターフェースから、「AIが必要な機能を画面上にその場で組み立てる」インターフェースへの決定的なパラダイムシフトです。

Vercel AI SDKとNext.js App Routerの組み合わせにより、これまで複雑な状態管理とWebSocket実装が必要だったコンポーネントストリーミングが、極めて簡潔かつ型安全に実現できるようになりました。単なるチャットボットにとどまらない、真に実用的なAIネイティブアプリケーションの構築に向けて、ぜひプロジェクトに導入してみてください。
